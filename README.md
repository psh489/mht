
### 1. 퍼블릭 서브넷과 프라이빗 서브넷의 차이 (라우팅 관점)
* **퍼블릭 서브넷**: 라우팅 테이블에 **인터넷 게이트웨이(IGW)**로 향하는 경로가 설정되어 있어, 외부 인터넷과 양방향 통신이 직접 가능합니다.
* **프라이빗 서브넷**: 인터넷 게이트웨이로 가는 경로가 없습니다. 대신 **NAT 게이트웨이**를 거쳐야만 외부로 나갈 수 있는 제한된 경로를 가집니다.

### 2. admin-ec2가 NAT Gateway를 통해 인터넷에 접근해야 하는 이유
* **보안 강화**: 외부에서 직접 서버로 들어오는 접속은 차단하면서, 서버 업데이트나 패치를 위해 내부에서 외부로 나가는 통신(Outbound)은 허용하기 위해서입니다.

### 3. web-ec2를 점프(바스천) 서버로 사용하는 이유
* **보안 관문 역할**: 프라이빗 영역에 있는 서버에 접속하기 위해 거쳐가는 유일한 통로로 설정함으로써, 공격 노출 면적을 최소화하고 접근 제어를 중앙화하기 위함입니다.

### 4. Elastic IP(EIP)의 목적과 무료 유지 조건
* **목적**: 인스턴스 재시작 시에도 바뀌지 않는 고정 공인 IP를 제공하기 위해 사용합니다.
* **무료 조건**: 실행 중인 EC2 인스턴스에 딱 1개의 EIP만 연결되어 있어야 합니다. 인스턴스가 중지되거나 연결되지 않은 상태로 방치되면 비용이 청구됩니다.

### 5. 실제 운영 환경에서 이 구조가 필요한 이유
* **계층적 방어**: 실제 기업 환경에서는 보안을 위해 웹 서버만 외부에 노출하고, 중요한 관리 서버나 DB는 내부망(Private)에 숨기는 이 구조를 표준으로 사용합니다.

## 2. Elastic IP 비용 관리 가이드

### Elastic IP가 무료인 조건
* **프리티어 계정:** 월 750시간까지 무료 제공 (2024년 2월 정책 변경 반영).
* **주의:** 미사용 중(Idle)이거나 750시간 초과 시 시간당 $0.005 부과.

### 실습 후 자원 정리 순서
1. **NAT Gateway 삭제:** 시간당 약 $0.045 발생하므로 가장 먼저 삭제.
2. **Elastic IP 릴리스:** '연결 해제'가 아닌 '릴리스(Release)'를 해야 비용이 중단됨.
